# M3 local development

M3 masih dalam pembangunan. Checkout lokal dapat menjalankan API/Web M0–M2 dan menguji fondasi runner/dispatch terhadap PostgreSQL. Plugin validation/materialization, signature verification, dan lease-scoped delivery tersedia sebagai komponen internal. Belum ada agent runner Claude, sandbox, atau endpoint payload/plugin yang membuat `agent_execute` berjalan end-to-end.

Adapter HTTP binary untuk payload dan plugin runner sudah diuji dalam komposisi Nest terisolasi. Keduanya menuntut otoritas runner, kontrak request yang ketat, batas respons masing-masing 1 MiB dan 16 MiB, serta respons tanpa cache. Adapter dapat memakai service internal yang memeriksa lease/binding pada kedua sisi decrypt atau download. Controller belum terdaftar di `AppModule`, sehingga route tidak tersedia dari API lokal/produksi. Production KMS/storage dan signer trust/provenance wiring tetap prasyarat aktivasi; test HTTP memakai delivery fixture, bukan membuktikan pengiriman end-to-end.

Daftar runner operator `/api/v1/runners` menampilkan `liveness` terpisah dari `status`. Setelah heartbeat dengan revision registrasi terkini, liveness menjadi `ALIVE`; tanpa presence terkini menjadi `OFFLINE`. Jika coordination store gagal dibaca, UI/API menerima `UNKNOWN`, bukan menyimpulkan runner offline. Liveness tidak mengizinkan retry/reassignment atas attempt yang sudah `ORPHAN_SUSPENDED`.

Paket runner memiliki `LocalSandboxSupervisor` sebagai boundary lifecycle lokal untuk adapter sandbox yang kelak dipilih. Ia mengikat satu launch ke assignment/boot/generation/epoch, menahan duplicate launch, meminta stop lalu eskalasi berbatas waktu, dan hanya menghasilkan `TERMINATED` bila adapter membuktikan seluruh sandbox/process tree sudah exit. Port `recover` dapat menemukan sandbox dari proses supervisor sebelumnya; binding lengkap diperiksa sebelum sinyal stop dikirim. Launch/lookup terlambat, binding yang tidak cocok, kegagalan inspeksi, atau sandbox yang tidak ditemukan menghasilkan `UNCONFIRMED`. Ini belum meluncurkan proses produksi, belum membuktikan efek eksternal selesai, dan belum memberi izin reassignment.

Untuk drain lokal, `quiesce()` langsung menolak launch baru dan mengembalikan snapshot assignment yang sudah tercatat tanpa menghentikan pekerjaan aktif. Pemilik lifecycle memutuskan deadline in-flight; setelah cancel atau deadline, `stopTracked()` meminta stop untuk snapshot itu dan mengembalikan bukti per assignment. Ini belum terhubung ke drain pool, cancel intent durable, atau shutdown runner produksi.

Supervisor lokal menahan maksimal 256 identitas sepanjang umur proses agar tidak tumbuh tanpa batas. Belum ada durable stop receipt atau retirement protocol untuk melepas identitas dengan aman, sehingga primitive ini belum cocok untuk worker produksi berumur panjang.

Pilihan adapter sandbox tetap O03. [Evaluasi sandbox](../security/SANDBOX-EVALUATION.md) mencatat input deployment, kandidat, dan eksperimen keamanan/recovery yang harus dibuktikan sebelum adapter produksi dipilih.

## Persiapan lokal

Gunakan Node 24 dan root `.env` yang dibuat mengikuti [configuration guide](CONFIGURATION.md). Bila PostgreSQL dikelola oleh repo, siapkan PostgreSQL binaries sesuai [M0 guide](M0.md). Perintah dari root repo:

```powershell
npm ci
npm run env:init
npm run db:start
npm run db:migrate
npm run dev
```

`npm run dev` menjalankan aplikasi lokal. Jangan memakai test key provider untuk data nyata: ia hanya dipakai oleh unit/integration tests dan tidak menyediakan KMS produksi. Mode `m0-local` memakai in-memory runner presence/lease; ia berguna untuk development satu proses, bukan bukti failover multi-node.

## Pemeriksaan fondasi M3

Di terminal terpisah setelah database siap:

```powershell
npm run test:m3:foundation
npm run test:integration
```

Tes di atas membuktikan admission envelope, pull claim, exact runner lease, epoch fence, scoped payload-read authorization, tool-effect intent/status recovery dengan receiver fixture, registry plugin dengan signature Ed25519 nyata dan test signing key, delivery yang menolak revokasi selama download, serta validasi/materialisasi file paket plugin ke direktori sementara. Reader S3 diuji dengan stream fixtures untuk ukuran palsu, truncation, timeout, dan abort. Tes integrasi M1 membuktikan profile pinning, snapshot, dan revocation fence sebelum admission; dispatch claim mengirim metadata paket tanpa object key. Mereka tidak menjalankan Claude SDK, kode plugin, trust-root produksi, atau sandbox. `npm run test:runner:redis` perlu Redis terpisah pada `M3_COORDINATION_REDIS_URL`; `npm run test:dispatch:s3` dan `npm run test:plugin:s3` perlu object store S3-compatible disposable sesuai workflow CI. Jangan mengarahkan tes itu ke service/data produksi. Format signature dan batas production wiring ada pada [plugin contract](../contracts/TOOLS-PLUGINS.md#signature-dan-delivery-internal-v1).

Status dan gap terbaru ada di [CURRENT-STATE](../implementation/CURRENT-STATE.md), [PLAN](../PLAN.md), dan [acceptance gates](../testing/ACCEPTANCE.md).
