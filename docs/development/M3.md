# M3 local development

M3 masih dalam pembangunan. Checkout lokal dapat menjalankan API/Web M0–M2 dan menguji fondasi runner/dispatch terhadap PostgreSQL. Plugin validation/materialization, signature verification, dan lease-scoped delivery tersedia sebagai komponen internal. Belum ada agent runner Claude, sandbox, atau endpoint payload/plugin yang membuat `agent_execute` berjalan end-to-end.

## Persiapan lokal

Gunakan Node 24 dan root `.env` yang dibuat mengikuti [configuration guide](CONFIGURATION.md). Bila PostgreSQL dikelola oleh repo, siapkan PostgreSQL binaries sesuai [M0 guide](M0.md). Perintah dari root repo:

```powershell
npm ci
npm run env:init
npm run db:start
npm run db:migrate
npm run dev
```

`npm run dev` menjalankan aplikasi lokal. Jangan memakai test key provider untuk data nyata: ia hanya dipakai oleh unit/integration tests dan tidak menyediakan KMS produksi. Mode `m0-local` memakai in-memory runner presence/lease; ia berguna untuk development satu proses, bukan bukti failover multi-node.

## Pemeriksaan fondasi M3

Di terminal terpisah setelah database siap:

```powershell
npm run test:m3:foundation
npm run test:integration
```

Tes di atas membuktikan admission envelope, pull claim, exact runner lease, epoch fence, scoped payload-read authorization, tool-effect intent/status recovery dengan receiver fixture, registry plugin dengan signature Ed25519 nyata dan test signing key, delivery yang menolak revokasi selama download, serta validasi/materialisasi file paket plugin ke direktori sementara. Reader S3 diuji dengan stream fixtures untuk ukuran palsu, truncation, timeout, dan abort. Tes integrasi M1 membuktikan profile pinning, snapshot, dan revocation fence sebelum admission; dispatch claim mengirim metadata paket tanpa object key. Mereka tidak menjalankan Claude SDK, kode plugin, trust-root produksi, atau sandbox. `npm run test:runner:redis` perlu Redis terpisah pada `M3_COORDINATION_REDIS_URL`; `npm run test:dispatch:s3` dan `npm run test:plugin:s3` perlu object store S3-compatible disposable sesuai workflow CI. Jangan mengarahkan tes itu ke service/data produksi. Format signature dan batas production wiring ada pada [plugin contract](../contracts/TOOLS-PLUGINS.md#signature-dan-delivery-internal-v1).

Status dan gap terbaru ada di [CURRENT-STATE](../implementation/CURRENT-STATE.md), [PLAN](../PLAN.md), dan [acceptance gates](../testing/ACCEPTANCE.md).
