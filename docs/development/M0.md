# Menjalankan M0 — Contract Lab

M0 adalah UI + backend + PostgreSQL yang dapat dicoba lokal. Tidak ada model, agent, plugin, atau tagihan AI yang dijalankan. Gunakan data sintetis; jangan masukkan dokumen sensitif atau credential.

## Stack dan source

NestJS + FastifyAdapter + Prisma/PostgreSQL; frontend React/Next.js App Router. Batas source: [CODE-STRUCTURE](../architecture/CODE-STRUCTURE.md). Keputusan: [ADR-0016](../adr/0016-nestjs-fastify.md), [ADR-0017](../adr/0017-prisma-postgresql.md), [ADR-0018](../adr/0018-clean-architecture-quality.md).

Yang benar-benar dijalankan pada M0:

1. NestJS + Fastify + Prisma + PostgreSQL.
2. Clean Architecture + automated dependency/cycle rules.
3. React/Next.js App Router + TypeScript frontend.
4. Shared typed contracts/schema + generated JSON Schema/OpenAPI.
5. Contract validation untuk `chat`, `generate`, `structured_generate`, `agent_execute`.
6. Local app isolation + idempotency + PostgreSQL persistence.
7. Tidak ada provider call, agent execution, atau billing.
8. `/v1/*` masih planned dan tidak live.
9. M0 sendiri tidak mengimplementasikan Application Registry production, Keycloak, AI Connections, Plugin Registry, atau distributed runners. Slice registry M1 dikembangkan terpisah; capability berikutnya tetap P1–P3.
10. Seluruh capability M0 berstatus `CONTRACT_ONLY` pada [Capability Catalogue](../contracts/CAPABILITIES.md).

## Jalankan

Prerequisite: Node 24.x yang kompatibel dengan versi package-lock dan PostgreSQL binaries. Workstation saat pengembangan memiliki Node 24.11.1 dan PostgreSQL 15.5; versi PostgreSQL ini bukan rekomendasi patch produksi.

```powershell
cd D:\Ansha\architecture-description\ai-runtime-platform
npm ci
npm run contracts:export
npm run dev
```

Dev command membangun shared contracts, generate Prisma client, membuat/memulai cluster khusus jika belum ada, menjalankan Prisma migration + seed, mengompilasi backend Nest, lalu menunggu API ready sebelum menjalankan FE. Frontend memakai Next.js HMR dan BFF server-side; perubahan backend/shared-contract memerlukan restart dev command. Buka `http://127.0.0.1:4310`, lalu pilih **Open local console**; Contract Lab berada di `/contract-lab`. Liveness API: `http://127.0.0.1:4311/health/live`. Endpoint data memerlukan app credential; browser memakai proxy lokal sehingga token tidak perlu disalin ke UI.

`.env` adalah **single configuration gate** untuk M0 lokal. Semua nilai deployment/runtime/tooling yang configurable dibaca dari env melalui `config/environment.mjs`; tidak ada `.local/config.json`, auto-detection PostgreSQL, port fallback, browser fallback, atau `DATABASE_URL` fallback. Missing/invalid required variable membuat command fail-fast. `npm run env:init` hanya membuat `.env` secara eksplisit dari `.env.example` dan generate secret lokal; command menolak overwrite file yang sudah ada. Detail lengkap: [CONFIGURATION](CONFIGURATION.md).

Port sibuk menyebabkan start gagal, bukan membunuh proses lain. Cluster bukan Windows service global. `Ctrl+C` menghentikan FE/BE yang dimulai command; DB tetap hidup agar data terjaga. `npm run db:stop` hanya menghentikan cluster milik repo tanpa menghapus data. `npm run db:start` memulainya kembali. Jangan menjalankan dua dev command untuk port yang sama.

## Resep uji manual

1. Pilih **Direct chat**. Payload tidak memiliki job/plugin. Klik **Validasi & simpan**: hasil valid, execution tidak dibuat, record DB bertambah.
2. Kirim payload sama dengan idempotency key sama: record tetap sama dan response replay ditandai. Ubah payload tetapi key sama: 409 conflict. Klik key baru untuk pemeriksaan baru.
3. Pilih **Structured output** lalu **Scribe agent**. Lihat capability/profile berbeda, context job hanya pada contoh yang membutuhkan. Artifact references hanya diperiksa bentuknya, bukan existence/permission.
4. Pilih **Identity spoofing**: field application_id ditolak. Pilih profile yang tidak cocok atau naikkan limit melampaui profile: report invalid dengan alasan.
5. Buka **Riwayat validasi**, refresh browser, lalu baca record. Data berasal dari PostgreSQL, bukan localStorage. Halaman **Schema explorer** dan **Panduan fase** menjelaskan kontrak dan batas masing-masing fase.

Kontrak invalid tetap bisa memiliki HTTP 201 karena endpoint lab berhasil menyimpan laporan pemeriksaan. Ini bukan status admission API eksekusi. Schema `/v1/*` di file planned OpenAPI belum diimplementasikan dan tidak mengirim request model.

## Perintah pemeriksaan

```powershell
npm run verify
npm run test:e2e
npm run db:inspect
```

`verify` menjalankan Prettier check, ESLint, inward dependency/cycle rules, typecheck source/tests/tooling, unit contracts/use cases/rules, Nest/Prisma integration, schema drift, build, dan tautan docs. Jalankan `npm run setup` dahulu bila hanya ingin menguji tanpa dev server. Browser/channel, ports, PostgreSQL management, credentials, timeout, pool, dan local paths semuanya berasal dari `.env`; tidak ada fallback platform-specific di code.

Integration tests memakai idempotency key milik test lalu membersihkan record test itu saja. Browser smoke tests meninggalkan beberapa record demo sehingga history dapat dipelajari. Jangan menjalankan suite ini terhadap database production; config secara eksplisit menolaknya.

## Struktur implementasi

`packages/contracts`: Zod/types, bounded schema checks, fixtures. `contracts/`: generated JSON Schema dan OpenAPI (aktif M0 vs planned v1). `apps/api`: auth lokal, validator, persistence dan scoped history. `apps/web`: UI/proxy. `prisma/schema.prisma` dan `prisma/migrations`: schema/migration aktif. `db/migrations`: historical baseline compatibility, jangan mengedit SQL yang sudah applied. `scripts`: bootstrap, export, inspection dan dev runner. Test evidence: [M0](../milestones/M0.md).

M0 menyimpan digest, structural counts, known field names dan laporan validasi; tidak menyimpan nilai prompt/messages mentah. Nama property dalam error path dan input identifiers tetap dapat menjadi metadata: gunakan data sintetis. Tidak ada retention/deletion policy produksi atau security certification yang diwariskan dari lab ini.

## Troubleshooting

Koneksi DB gagal: jalankan `npm run db:start`, periksa path yang dideklarasikan oleh `M0_POSTGRES_LOG_FILE`, dan pastikan host/port di `.env` benar serta tidak dipakai proses lain. Migration checksum mismatch berarti file migration lama berubah; buat migration baru, jangan menimpa data. `.local` tidak dibagikan atau di-commit. Jangan menghapus `.local/postgres` untuk mengatasi error tanpa keputusan eksplisit menghapus seluruh data demo.

Bootstrap dan API M0 memakai credential cluster lokal yang sama untuk kesederhanaan lab. Ini tidak menjadi pola role/privilege database produksi; pemisahan migration/runtime credentials harus dilakukan sebelum deployment nonlokal. Metadata demo disimpan sampai user memilih menghapus/reset; tidak ada auto-retention produksi pada M0.

## Prisma dan migrasi yang aman

`npm run db:generate` menghasilkan client dari schema. `npm run db:migrate` memverifikasi/baseline database lama lalu menjalankan migrate deploy dan seed; tidak melakukan reset. `npm run db:inspect` memakai Prisma untuk membaca metadata. `npm run db:format` memformat Prisma schema, bukan SQL migration historis. Buat migration baru untuk perubahan schema; inspeksi diff/backup sebelum deploy.

CI di `.github/workflows/verify.yml` menggunakan PostgreSQL disposable dan commands yang sama. SQL baseline fresh dan existing harus tetap kompatibel. Workflow didefinisikan di repo; status run GitHub tidak diasumsikan dari tes lokal Windows.

## Target architecture not implemented by M0

Application Registry production, Keycloak federation, AI Connection/Credential Binding, Admin UI management, Plugin Registry, distributed runner self-registration/placement, runner-local credentials, Vault integration, MCP remote tools, dan workspace artifact promotion adalah target M1–M3. M0 local app credential dan demo profiles tidak boleh dianggap implementasi fitur tersebut.
