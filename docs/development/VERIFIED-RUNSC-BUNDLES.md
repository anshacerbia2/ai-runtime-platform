# Pinned rootfs content and runsc bundles

**20 October 2026: M3 content-verification checkpoint, not production image approval or O03 closure.** [`FileRunscBundleProducer`](../../apps/runner/src/file-runsc-bundle-producer.ts) copies approved file-tree contents into an assignment-specific OCI bundle and verifies the resulting artifact before reservation. [`runsc-bundle.ts`](../../apps/runner/src/runsc-bundle.ts) defines canonical manifest encoding and the fixed experimental OCI preset. [ADR-0011](../adr/0011-sandbox-security.md) is unchanged.

## Trust input and supported subset

The host supplies an independently approved manifest digest, manifest, existing private image/bundle roots and a fixed map of named programs. These are trusted host configuration, never application/plugin/request parameters. Computing a digest of untrusted incoming data does not approve it. Production approval/signature/provenance resolution, registry/layer import, patch/revocation and release policy remain unwired.

Internal `ai-runtime-rootfs/v1` is a **file-tree manifest**, not an OCI registry image or layer digest. Its canonical JSON binds architecture, sorted directories, and sorted regular files with relative path, exact byte count, SHA-256 and executable bit. It permits at most 256 directories and 256 files, depth eight, paths up to 240 ASCII characters, 128 MiB per file, 256 MiB total and 128 KiB manifest metadata. Parent directories must be declared; `/dev`, `/proc` and `/tmp` are empty mountpoints. Links, devices, sockets, undeclared files, traversal and unknown fields are unsupported. This deliberately narrow subset does not assert compatibility with an arbitrary OCI/Claude image.

Linux source and bundle roots must be disjoint canonical private directories owned by the effective UID. Source child directories use 0555; files use 0444 or 0555 according to the manifest, with one link and no setuid/setgid/write bits. FD-anchored traversal and no-follow opens reject links/replaced roots. The entire source tree is visited, not only listed files.

## Production and verification

Only a configured program name can select a fixed argv whose executable is an approved executable file. No caller env, mount, hook, UID, raw OCI field or resource override is accepted. The preset uses UID/GID 65532, no-new-privileges, empty capabilities, readonly `rootfs`, private namespaces and the same bounded proc/dev/tmp/cgroup settings as the candidate experiment. Native host composition must also enforce the pinned runsc version and `systrap`/`network=none` flags; an OCI config alone does not enforce those CLI choices. [OCI readonly/process contract](https://github.com/opencontainers/runtime-spec/blob/v1.0.2/config.md).

Preparation exclusively creates the deterministic assignment directory, copies bytes to **new inodes** in 64 KiB chunks while checking size/hash, makes rootfs files/directories readonly, then writes private readonly canonical manifest/config metadata. File and directory fsync complete before a verified receipt is returned. The receipt carries the full record, config digest and approved rootfs-manifest digest; the latter is also in the OCI annotations and therefore bound by the config digest stored in [launch reservations](RUNSC-LAUNCH-STORE.md).

`verify` rereads exact config/manifest bytes, permissions and every rootfs file/hash, rejecting additions, links and tampering. Content verification does not prove code safety, executable compatibility, absence of embedded secrets or supply-chain origin. Trusted host administrators remain outside this filesystem protection boundary; readonly permissions are not fs-verity or tamper resistance against root. Host ownership must preserve verified bundles through launch.

## Lifecycle and evidence

Four operations including active work may be admitted, with at most 256 tracked bundle IDs per producer lifetime. Async I/O is serialized; byte/queue bounds are not a disk-latency guarantee. Same-instance exact retries share one preparation; identity/program conflicts fail. Failed/partial artifacts are retained without overwrite or automatic deletion. Storage/verification failure seals the instance. Close drains admitted I/O; it is not a sandbox-stop proof.

Reopen with any existing bundle is readonly: it can verify an exact old binding/program but cannot prepare fresh work or adopt a partial directory for execution. Neither a receipt nor successful verification grants execution authority. The [driver](RUNSC-DRIVER.md) still checks authority after asynchronous preparation, and the launch store still decides whether a reservation is fresh. Runtime absence, clean producer close or image verification cannot retire an assignment or authorize retry/reassignment.

Cross-platform tests cover canonical pins, strict manifest/path limits and fixed OCI policy. Linux tests cover independent copies, readonly nested trees, invalid/changed content, links, undeclared files, config/manifest/rootfs tampering, bounded intake/close and readonly reopen. Real gVisor conformance now composes producer → verification → reservation → driver/supervisor → runsc. Its inert BusyBox bytes have an independently committed SHA-256 pin; the fixture approval manifest also includes a deliberately incompatible executable to preserve startup-uncertainty testing. A same-size rootfs mutation is denied before reservation or runtime dispatch.

This remains an inert CI fixture host: no Claude SDK/provider call, real credential/input handoff, broker egress, actual VPS approval, live-orphan host recovery or full worker/shared-store fencing. The real probe currently requires x64 before filesystem mutation because only its BusyBox bytes are pinned; ARM64 producer/schema support is not ARM64 runtime conformance. O03/O06/O14/O15 remain open. Next work is native host lifecycle/recovery and trusted release/credential composition, then runtime compatibility/bridge and remaining gates. No API, migration or ADR change.
